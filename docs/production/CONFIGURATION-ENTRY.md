# إدخال البيانات وتفعيل الخدمات من لوحة المالك

المسار الأساسي الآن **`/admin/integrations` — الربط والتفعيل**. يتطلب حساب مالك، والتحقق الثنائي، وإعادة إدخال كلمة مرور المالك لكل تغيير. لا ترسل الأسرار في المحادثة.

1. اختر الخدمة وأدخل الحساب والمفاتيح. الحقول السرية لا تعيد عرض المفتاح؛ تركها فارغة يحتفظ بالقيمة، وحذفها يحتاج اختيارًا صريحًا.
2. اضغط **حفظ المسودة**. تُشفّر على الخادم بمفتاح ENCRYPTION_KEY، مع رقم نسخة وسجل تدقيق دون الأسرار. لا تستبدل النسخة العاملة.
3. **اختبار دون خصم أو إرسال** يفحص اتصال الحساب؛ لا يُنشئ حجزًا أو فاتورة دفع أو تحويلًا أو رسالة.
4. **اختبار وتفعيل** يفعّل النسخة فقط بعد نجاح الفحص وعدم تغيّر المسودة أثناءه. الاختبار لا يعتمد تلقائيًا صلاحية الحساب التجارية أو تسوية الأموال أو التوقيع القانوني.
5. **إيقاف العمليات الجديدة** يحتفظ ببيانات الربط لمتابعة المدفوعات والتحويلات التي بدأت سابقًا. لا تغيّر الحساب المرتبط بعمليات معلقة إلى حساب آخر قبل تسويتها.

الواجهات الجاهزة: دفع MyFatoorah؛ تحويل الموردين عبر بروتوكول جهة التحويل؛ SMTP أو Resend؛ Twilio للرسائل وواتساب؛ الموافقة الداخلية أو جهة التوقيع الخارجية؛ بيانات الاستضافة والنسخ واختبار الأجهزة.

**مهم:** إعدادات الاستضافة تُحفظ كبيانات نشر مطلوبة. تغيير DNS أو قاعدة الخادم أو النسخ الاحتياطي يحتاج تنفيذًا على الاستضافة؛ لن تدّعي اللوحة أنها نفذت ذلك. الأساس اللازم لتشغيل اللوحة نفسها (قاعدة البيانات ومفتاح تشفير الأسرار ومفتاح الجلسات) يُهيّأ في بيئة الخادم قبل أول دخول.

بيانات الشركة والسياسات وجدول الدفعات في **`/admin/settings`**. التسويات والمستفيدون في **`/admin/settlements`** وملف المورد. متابعة تسليم الرسائل في **`/admin/deliveries`**؛ قبول الرسالة لا يساوي تسليمها.

لا توجد حسابات دفع أو بنك أو توقيع معتمدة مفعلة تلقائيًا. ربط البنك والتوقيع يتطلب اختيار الجهة، واعتمادها، وتنفيذها لبروتوكول الربط أو إضافة موصل خاص بواجهتها؛ ليس مجرد إدخال أي رابط ومفتاح.

## إعداد الخادم الأولي وبديل الإدخال المحلي


تم تجهيز فصل بيانات الشركة عن الأسرار. لا تُرسل مفاتيح الخدمات أو كلمات المرور في المحادثة.

## الملفات الجاهزة

نفّذ `npm run setup:prepare`. ينشئ عند غيابها فقط:

- `.env`: إعدادات الخادم، مع توليد COOKIE_SECRET وENCRYPTION_KEY وMETRICS_TOKEN عشوائية وثابتة. لا يطبع قيمها، ولا يستبدل ملفًا موجودًا أو يغير المفاتيح عند تكرار الأمر.
- `data/business-settings.json`: حقول الشركة والسياسات والأسعار دون بيانات افتراضية وهمية. المجلد مستبعد من Git.

## الدومين والاستضافة في .env

| الحقل | أدخل |
|---|---|
| APP_HOST | اسم النطاق فقط، دون https أو مسار |
| APP_ORIGIN | https:// متبوعًا بنفس النطاق |
| NODE_ENV | production عند النشر؛ اترك development محليًا |
| DEPLOYMENT_ENV | يفرض Compose قيمة production افتراضيًا؛ أضف staging صراحةً لبيئة اعتماد تستخدم Sandbox |
| DATABASE_URL | اتصال PostgreSQL الخاص بالبيئة؛ PGlite محلي فقط |
| POSTGRES_PASSWORD / DB_APP_PASSWORD | كلمتا مرور مختلفتان عشوائيتان؛ الثانية32 محرفًا على الأقل، URL-safe مع Compose |
| BOOTSTRAP_OWNER_EMAIL/NAME/MOBILE/PASSWORD | بيانات أول مالك؛ كلمة مرور قوية، لا حساب افتراضي |
| BOOTSTRAP_MFA_SECRET | سر Base32 خاص بتطبيق مصادقة المالك، إلزامي في Production |

احتفظ بمفاتيح Cookie/AES ثابتة عبر نسخ التطبيق وإعادة التشغيل. لا تستبدل مفتاح AES دون إعادة تشفير أسرار MFA. أبقِ ملف .env خارج المجلد العام والنسخ المشتركة.

## الدفع والبريد

املأ MYFATOORAH_API_KEY وMYFATOORAH_WEBHOOK_SECRET وحدد MYFATOORAH_ENVIRONMENT=sandbox في بيئة اختبار، وlive فقط بعد اعتماد التاجر واختبارات التسوية. عنوان Webhook هو APP_ORIGIN متبوعًا بـ `/api/webhooks/myfatoorah`. لا تُدخل أي بيانات بطاقات داخل النظام.

املأ SMTP_HOST/PORT/USER/PASSWORD وMAIL_FROM وSMTP_SECURE، وتحقق من اعتماد المرسل. ضع بريد مسؤول التشغيل في OPERATIONS_EMAIL. باقي المتغيرات الاختيارية وTwilio وSentry موثقة في INTEGRATIONS.md.

## بيانات الشركة

افتح `data/business-settings.json` واملأ companyName وregistrationNumber وcontactEmail وcontactPhone وterms وprivacy وcancellation بالنصوص القانونية المعتمدة. اضبط taxRate وفق المراجعة المحاسبية، وجدول deposit/second بحيث لا يتجاوز مجموعهما100؛ الباقي الدفعة النهائية. تظل الموافقتان المستقلتان إلزاميتين.

بعد تهيئة قاعدة البيانات والمالك، نفّذ `npm run setup:business`. يرفض القيم الفارغة/غير الصالحة ويطبق الإعدادات عبر خدمة الأعمال مع سجل تدقيق. لا ينشئ حساب مالك ولا يفعّل مزود دفع ولا يرفع بيئة Production تلقائيًا. يمكن تعديل نفس حقول الشركة لاحقًا من `/admin/settings` بحساب المالك؛ الأسرار لا تظهر هناك.

## التحقق قبل التفعيل

نفّذ `npm run audit:launch`. لا تملأ حقول مراجع الاعتماد SANDBOX_CERTIFICATION_REFERENCE وRESTORE_DRILL_REFERENCE وSECURITY_REVIEW_REFERENCE إلا بروابط أو أرقام مراجعات نُفذت فعلًا. يتطلب الإطلاق اختبار الدفع والاسترداد والإشعارات وTLS والنسخ والاستعادة على الاستضافة المختارة، لا مجرد وجود المتغيرات.

راجع READINESS.md للبوابات المفتوحة التي تحتاج تنفيذًا أو اعتمادًا إضافيًا إلى جانب إدخال البيانات.

## تسويات الموردين

حقول SUPPLIER_PAYOUT_PROVIDER وSUPPLIER_PAYOUT_ENVIRONMENT وSUPPLIER_PAYOUT_BASE_URL وSUPPLIER_PAYOUT_API_KEY وSUPPLIER_PAYOUT_WEBHOOK_SECRET مضافة إلى .env. أدخل مرجع المستفيد الصادر من الجهة المعتمدة في ملف المورد من لوحة المالك. إعداد Provider=bridge يتطلب خدمة تحويل فعلية تنفذ البروتوكول الموثق، وليس مجرد رابط أو مفتاح تاجر الدفع للعملاء. راجع SUPPLIER-SETTLEMENTS.md قبل التفعيل. لا يُرسل تحويل دون الموافقتين، ولا يُعرض كمسدد دون تحقق من الجهة.
